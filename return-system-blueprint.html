Architecture

Agent 4 is the only public entry point. It is an MCP client toward Agents 1 to 3, and an MCP server plus a REST API toward everyone else.

One return

  1. The browser posts the complaint to Agent 4 with a JWT. Agent 4 stores the raw text encrypted.
  2. Agent 1 sanitises, redacts personal data, fixes typos, matches the product and extracts fields. Only clean_text continues.
  3. Agent 2 classifies the root cause, lists the words behind it and adds an abuse signal.
  4. Agent 3 retrieves evidence for the product, the issue and the top candidate causes.
  5. Agent 4 checks that the evidence supports the cause, and retries with an expanded query if not.
  6. Agent 4 writes a cited summary, applies the policy rules, flags human review, logs and meters the run, and returns the decision card.

A bulk upload

  1. An admin uploads a CSV. Agent 4 validates it and creates a job.
  2. Agent 1 processes rows in batch. Each row then goes through the single-return steps, eight at a time.
  3. Agent 2 clusters the whole set and ranks products, suppliers and batches by impact.
  4. The dashboard shows decisions, root causes, findings and a short executive summary.

2. Root cause from Agent 2.
3. Build the retrieval query from product + issue + the names of the top 2 candidate labels. Call retrieve_evidence with filters {"hints": [...], "product_id": ...}.

5. Reflect: if evidence_support < 0.4 and attempts < 2, re-query with expanded terms and the second candidate. If it is still low, keep going but add risk flag "weak_evidence".
